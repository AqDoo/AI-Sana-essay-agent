# Развёртывание проекта

Два сценария: **быстрый показ на своём ПК** и **развёртывание на сервере вуза**.

---

## Вариант A — показать на одном компьютере (демо / защита)

Ничего дополнительно ставить не нужно, кроме Python.

```bash
# 1. Установить зависимости
pip install -r requirements.txt

# 2. Настроить ключи
cp .env.example .env
# Открыть .env и вписать GEMINI_API_KEY и SERPER_API_KEY

# 3. Запустить
streamlit run app.py
```

Откроется браузер на `http://localhost:8501`. Готово для показа.

Если нужно, чтобы с этого же компьютера могли зайти другие люди в той же сети (например, показать с проектора и дать ссылку комиссии на телефон):

```bash
streamlit run app.py --server.address 0.0.0.0
```

Тогда приложение доступно по `http://<IP-этого-компьютера>:8501` всем в локальной сети.

## Вариант B — развёртывание на сервере (через Docker)

Рекомендуемый способ для постепенного внедрения — сервер настраивается один раз, дальше просто `docker compose up`.

### Требования к серверу
- Docker + Docker Compose установлены
- Исходящий доступ в интернет к `generativelanguage.googleapis.com` (Gemini) и `google.serper.dev` (Serper)
- Открыт порт 8501 (или другой, на который вы его пробросите)

### Шаги

```bash
# 1. Скопировать проект на сервер (git clone / scp / архивом)

# 2. Настроить ключи
cp .env.example .env
nano .env   # вписать GEMINI_API_KEY, SERPER_API_KEY, при желании APP_PASSWORD

# 3. Собрать и запустить
docker compose up -d --build

# 4. Проверить, что контейнер работает
docker compose ps
docker compose logs -f
```

Приложение будет доступно на `http://<IP-сервера>:8501`.

### Остановить / обновить
```bash
docker compose down          # остановить
docker compose up -d --build # пересобрать и запустить после изменений в коде
```

### Доступ по домену и HTTPS (опционально)
Для публичного адреса с сертификатом поставьте перед контейнером nginx или Caddy как reverse proxy — Caddy сам получает Let's Encrypt сертификат:

```
# Caddyfile
essay.your-university.kz {
    reverse_proxy localhost:8501
}
```

## Защита паролем

В `app.py` уже встроена простая защита: если в `.env` задан `APP_PASSWORD`, при заходе на сайт сначала спросит пароль. Один общий пароль на всех — этого достаточно для пилота на кафедре. Если понадобятся отдельные логины для каждого преподавателя — это следующий этап доработки (например, через `streamlit-authenticator` с базой пользователей).

---

## Известные ограничения текущей версии (для честности с заказчиком)

- **Общий лимит API на всех пользователей**: бесплатный тариф Gemini — 1500 запросов/день, Serper — 2500 запросов разово (не в день). При активном использовании несколькими кафедрами лимит исчерпается быстро — потребуется платный тариф.
- **Нет истории проверок**: результаты не сохраняются в базу, только скачиваются файлом. Для отчётности по группам/семестрам нужна БД — это следующий этап.
- **Один общий пароль**, а не личные кабинеты — этого достаточно для пилота, не для эксплуатации в масштабах вуза.

Эти пункты стоит явно проговорить на защите — как **план развития**, а не как недоработку: то, что показывается завтра, — рабочий пилот, готовый к постепенному внедрению на 1 кафедре / 1 ПК.
